# Pattern Analysis

The repository already used durable Markdown stories, schemas, a generated index,
and repository-local skills. The selected decision is **adapt**: keep those
contracts while changing artifact locality and separating definition refinement
from executable planning. GitHub Spec Kit's specification/planning separation,
embedded projects' evidence ladders, and narrow agent skills are useful
precedents; team-sized ceremonies and framework-mandated mocks are not.

The smallest sufficient change is a directory dossier plus one `plan-story`
skill. Test doubles are selected by seam and limitation (dummy, stub, fake, spy,
mock, simulator, fixture), not by fashion. Proof-of-concept work is a bounded
`spike` task with retained output and explicit success/failure branches.
